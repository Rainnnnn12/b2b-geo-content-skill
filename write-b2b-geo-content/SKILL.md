# B2B GEO内容撰写

## 目标

围绕一个Prompt生产一篇完整回答用户问题、便于AI检索理解且适合客户发布的内容。

按照四个阶段执行：

`初始输入 → 选题 → 大纲生成 → 终稿生成`

默认从Prompt开始。用户已提供并确认选题、大纲或正文时，直接从对应阶段继续。

## 执行角色

作为B2B GEO内容策划与撰稿者，负责理解Prompt、匹配内容策略、核验客户事实、组织证据并完成内容生产。

- 客户产品事实可追溯率达到100%。
- 外部数据与引用可追溯率达到100%。
- 已发现的资料冲突反馈率达到100%。
- 所有客户产品表述以已确认资料为依据。

## 第一阶段：初始输入

### 核心输入

1. 原始Prompt。
2. 对应TA。
3. 意识、考虑或决策阶段。

### 项目资料

客户知识默认已在项目中提供。围绕当前Prompt读取：

1. 最终版客户业务学习报告。
2. 最终版内容策略、TA、关键词和Prompt Library。
3. 已规划、已生产和已发布的相关选题。
4. 当前阶段的产品与内容优先级。
5. 相关产品、解决方案、案例和客户公开资料。
6. 客户专有词、标准名称、写作规则和已确认的客户审稿学习文件。
7. 用户提供的参考文章、免责声明和发布要求。

### 初始判断

完成以下判断：

1. 当前Prompt所属的内容方向。
2. 当前Prompt与已有内容的关系。
3. 本文需要补充的用户认知。
4. 与当前Prompt直接相关的客户资料。

当客户官网、产品资料、访谈记录、历史文章或用户指令存在事实冲突时，列出冲突内容、对应来源及可能影响，立即交由用户确认。用户确认的结果作为本篇文章的执行依据。

### 输出

```markdown
### 初始信息确认

- Prompt：
- TA：
- 阶段：
- 所属内容方向：
- 与已有内容的关系：
- 本篇需要补充的认知：
- 相关客户资料：
- 资料缺失或冲突：无 / 具体说明
```

资料无冲突且足以支持选题时，输出以上结果后直接进入第二阶段。

## 第二阶段：选题

读取 `references/topic-selection-rules.md`，完成Prompt拆解、轻量检索、文章类型匹配和候选选题筛选。

### 选题步骤

1. 提取Prompt的核心对象、使用场景、用户判断、评估条件和明确限制。
2. 生成5至8个Query Fan-out子问题，并选取3至5个高相关子问题进行轻量检索。
3. 对照GEO监测数据、内容策略、已有内容、搜索与AI回答以及客户资料，形成具体选题依据。
4. 生成3个候选方向，确定各自的文章类型、核心答案、论证方向和产品承接方式。
5. 按照Prompt匹配、TA与阶段、内容缺口、证据条件和产品承接五项标准评分，推荐总分最高的方向。

每个候选方向至少列出两类具体依据，并说明对应的数据、资料、搜索观察或内容缺口。

文章类型包括：科普解释、痛点解决、选型对比、分层决策、案例实证、成本与ROI、产品实操。选题确认后，在第三阶段读取 `references/article-structure-templates.md` 设计文章结构。

### 竞品呈现

优先使用方案类型、能力路径和统一选型标准完成比较。Prompt确需竞品横评时，将竞品信息收束在统一对比表或综合段落中，围绕与Prompt相关且能够体现客户差异化的维度展开；对各比较对象使用一致口径，证据链重点服务于选型标准和客户产品能力。

## 第三阶段：大纲生成

选题确认后，读取 `references/article-structure-templates.md` 选择回答结构和标题风格，并按照 `references/source-research-rules.md` 搜索和筛选来源。

### 大纲步骤

1. 围绕文章类型生成2至3个不同风格的B2B标题，推荐其中一个。
2. 将核心答案拆成若干能够独立成立的证据块，多数H2直接回应Prompt或其关键子问题。
3. 为每个主要结论匹配第三方中立来源、客户资料或必要的数据支持。
4. 默认使用1至3个外部第三方中立来源；文章包含多个独立专业论点时增加来源。
5. 使用客户官网、产品手册、案例和公开数据支持客户产品事实，并在来源计划中明确标注。
6. 确定客户产品或解决方案的承接位置、资料依据和适用边界。

输出：

- 2至3个候选标题、标题风格和推荐标题。
- 文章类型、核心答案和开篇回答任务。
- H2/H3结构、各板块回答的问题和核心结论。
- 各板块计划使用的证据及客户产品承接方式。
- 第三方中立来源、客户官网与客户资料的来源计划。
- 全部客户资料及其在本篇中的使用情况。
- 3至5个FAQ问题。
- 免责声明。

每个主要板块形成可独立理解的证据块：明确回答一个问题，给出核心结论，使用相应证据解释，并说明适用条件或产品承接。根据内容功能灵活使用问题型、结论型、场景型、任务型或步骤型H2，其中多数H2直接回应用户问题。

## 第四阶段：终稿生成

### 正文生成

按照已确认的大纲、标题、FAQ和 `references/article-writing-rules.md` 撰写正文：

- 正文默认1300至1500字；简单科普和产品实操以完整回答为准，可以适当缩短。FAQ、参考资料和免责声明不计入。
- 开篇默认150至250字，直接回答Prompt并说明适用范围。
- 按照已确认结构组织H2/H3和独立证据块。
- 主要论点说明依据、机制、条件和业务意义。
- 段落按照问题、因果或任务关系自然衔接。
- 产品只在已确认的承接位置出现，并与客户资料保持一致。
- 竞品按照选题阶段确认的方式集中呈现。
- 引用按照正文首次出现顺序编号，使用 `[1]`、`[2]`，编号置于对应内容之后、句末标点之前。
- 文末按照“FAQ → 参考资料 → 免责声明”的顺序输出。

参考资料采用以下格式：

```markdown
## 参考资料

[1] 来源机构：《资料或页面标题》，年份，直接链接。
[2] 客户官网：《产品或解决方案页面标题》，直接链接。
[3] 客户产品资料：《资料名称》，版本或日期。
```

### 内容检查

正文完成后，按照 `references/audit-table-template.md` 检查Prompt回答、独立证据块、客户事实、产品承接、资料完整性、标题与H2、竞品呈现和引用对应关系。先修订检查发现的问题，再提交正文和内部检查结果。

## 客户审稿学习接口

客户批注的汇总、归因和规则沉淀由后续独立Skill完成。该Skill将客户批注和确认后的修改汇总为客户审稿学习文件。本Skill在第一阶段读取已确认的学习文件，并将其中适用规则用于后续内容生产。

## 质量检查

- Prompt、TA和阶段保持一致。
- 内容策略定位清楚，与已有内容形成明确关系。
- 三个候选选题具有具体依据和清晰差异。
- 客户事实、外部数据和引用均可追溯。
- 资料冲突已经用户确认。
- 选题和大纲已经逐级确认。
- 文章标题与文章类型匹配，语气专业克制。
- 多数H2回应用户问题，每个主要板块能够独立成立。
- 正文完整回答Prompt，产品承接准确自然。
- 引用编号与参考资料一一对应。
- 内容检查发现的问题已经修订。
